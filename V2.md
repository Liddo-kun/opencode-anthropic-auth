## Login and persistence

The plugin registers integration `anthropic`, OAuth method ID `claude-pro-max`,
label `Claude Pro/Max`, through `context.integration.transform` and
`editor.method.update`. Existing key/environment methods are not replaced.

The authorization callback returns `IntegrationOAuthAuthorization` with
`mode: "code"`, the browser URL, instructions and a ten-minute `expiresAt`.
PKCE uses S256 and a cryptographically generated verifier and state. Anthropic's
existing registered hosted redirect remains
`https://platform.claude.com/oauth/code/callback`.

Open the supplied URL, authorize in the browser, then submit the complete callback
URL, `code#state`, or `code=...&state=...`. A bare code without state is rejected.
The callback verifies state before exchanging the code and is single-flight,
including completed exchanges, so duplicate submissions cannot spend the code
twice. A failed attempt must be restarted. There is no speculative loopback
redirect or automatic callback listener; the CLI/UI manages opening the browser
and collecting the returned code.

The callback returns `Credential.OAuth.make({ type, methodID, access, refresh,
expires })`. V2 owns creation and persistence in its credential API/database.
`expires` is an absolute Unix timestamp in milliseconds. The plugin neither
writes an auth JSON file nor imports daily credentials.

The public login API is:

1. `integration.oauth.connect({ integrationID: "anthropic", methodID:
   "claude-pro-max", location })`: POST `/api/integration/anthropic/connect/oauth`
   with `{ "methodID": "claude-pro-max" }`. Save the returned attempt ID and open
   its authorization URL.
2. `integration.oauth.complete({ integrationID: "anthropic", attemptID, code,
   location })`: POST `/api/integration/anthropic/connect/oauth/<attemptID>/complete`
   with `{ "code": "<callback URL or code#state>" }`. Successful completion stores
   the credential and returns HTTP 204.
3. `integration.oauth.status({ integrationID: "anthropic", attemptID, location })`
   polls `/api/integration/anthropic/connect/oauth/<attemptID>`; `oauth.cancel` uses
   DELETE at that same path. Keep the same Location query throughout the attempt.

From `/home/jon/code/Tandem-v2`, use the isolated launcher, which supplies the
development server's authentication environment:

```sh
/home/jon/.local/share/tandem-v2/toolchain/bun-1.4.2/bin/bun script/tandem-v2.ts cli auth login anthropic --method claude-pro-max --server http://127.0.0.1:4098
```

Requests select the active integration connection and use
`context.integration.connection.resolve(connection)`. V2 calls the registered
`refresh` callback within five minutes of expiry, then persists its returned
credential with `credentials.update` (`packages/core/src/integration.ts:696–713`).
Refresh preserves method ID and metadata, validates the token response, and never
logs token values or token-endpoint response bodies.

## Concurrent refresh

`src/refresh.ts` owns a module-shared map across Location plugin instances. All
callers presenting the same refresh token join one Promise. Successful rotations
remain in the map, so a late stale snapshot follows the rotated grant rather than
submitting the old token again. When a rotated grant itself expires, resolution
follows the rotation chain. Providers returning an unchanged refresh token can
refresh again only after that grant expires and without racing another caller.

Failed/ambiguous attempts remain failed for the process lifetime; the plugin does
not blindly retry a refresh token whose consumption is unknown. Reauthorization
is the recovery. Token calls have a thirty-second timeout. This is process-local
coordination, not a cross-process lease. Do not run two independent servers against
the same credential database: the public API has no credential compare-and-swap
or process-shared refresh lease. A process dying after remote rotation but before
the host persists the returned credential can require signing in again.

## Transport and subscription costs

The provider-scoped `session.hook("http.request", ..., { providerID: "anthropic" })`
is the final HTTP boundary for primary, title, generate and compaction requests.
It resolves the current OAuth credential, sets Bearer authorization, removes
`x-api-key`, merges required beta values, and uses
`claude-cli/2.1.280 (external, cli)`. It adds `beta=true` to `/v1/messages` when
absent. API-key and environment-key requests are returned untouched.

`ANTHROPIC_BASE_URL` retains its existing behavior: a valid HTTP(S) URL overrides
the outgoing API origin while preserving the request path/query. It does not
redirect authorization or token endpoints. It only applies to subscription
transport, as in the daily plugin.

Subscription model prices use v2's empty tier array (`cost = []`), as does the
built-in ChatGPT subscription plugin. This gives zero input/output/cache prices.
Credential switch/update events reload the original model catalog when the
subscription state changes, restoring normal prices for API-key connections.
Prompt, body and tool-name rewriting are not part of this plugin.

## Optional custom-endpoint TLS wrapper

TLS encrypts HTTPS traffic and normally checks that the server's certificate is
trusted and belongs to the requested host. `ANTHROPIC_INSECURE=1` or `true` skips
that certificate check for the explicitly configured custom API endpoint; it does
not turn off HTTPS encryption. Plain HTTP endpoints have no TLS or encryption.

With Claude Pro/Max selected and both variables enabled, the model transform
retargets only `@opencode/ai/providers/anthropic` to the local
`src/insecure-provider.ts`. All other catalog metadata remains intact except the
existing subscription zero-cost transform. Normal subscription requests (including
verified custom endpoints) keep the original native package. API-key connections
keep their native package, prices and transport; credential changes reload the
original catalog to restore those choices.

The wrapper delegates to the built-in Anthropic model, translating the custom
package's OAuth `apiKey` input into `authToken`. It preserves transport preparation
and execution, composing the existing HTTP middleware before matching the final
custom origin. Only that final host executor call gets a scoped
`FetchHttpClient.RequestInit` with Bun `tls.rejectUnauthorized = false`. There is
no second fetch, global TLS setting, or host-core edit. Exchange/refresh separately
pass `tls.rejectUnauthorized = true` to the fixed Anthropic token endpoint.

Limitations: pinned Bun 1.4.2 and the host's Effect fetch executor are required.
Custom/AI-SDK and `anthropic-compatible` packages are not retargeted; their OAuth
requests fail explicitly in insecure mode. The base URL overrides only origin,
not a path prefix or query. Invalid insecure base URLs fail explicitly. Reload
the plugin/server after environment changes. The exception includes redirects
followed internally by that one fetch. Current Anthropic supports summary
compaction through the same transport, not native explicit compaction operations.
See [V2-TRANSPORT.md](V2-TRANSPORT.md) for source evidence and acceptance steps.
